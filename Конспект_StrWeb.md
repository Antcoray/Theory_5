## 1. Общие сведения об HTML

**HTML (HyperText Markup Language)** — стандартный язык разметки документов в WWW, описывает семантическую структуру страницы. *Язык разметки не полон по Тьюрингу и не считается языком программирования.*

История: 1991 — первый черновик (18 элементов, Тим Бернерс-Ли, CERN); 1995 — HTML 2.0 (IETF — Internet Engineering Task Force, международная организация, разрабатывающая интернет-стандарты: формы, таблицы, карты изображений); 1997 — HTML 3.2 (W3C — World Wide Web Consortium, международный консорциум, определяющий стандарты веба; появился `div`); 1998–1999 — HTML 4.0/4.01 (Strict/Transitional/Frameset); 2014 — HTML5 (W3C Recommendation); параллельно WHATWG (Web Hypertext Application Technology Working Group — альтернативная рабочая группа, изначально созданная производителями браузеров) ведёт «HTML Living Standard» (с 2019 г. работают совместно с W3C).

*Где пригодится: понимание того, что HTML5 ввёл семантические теги и объявил многие старые атрибуты устаревшими — прямая подсказка, какими тегами и атрибутами пользоваться в ЛР1, а какими нельзя (они не пройдут валидацию).*

### Синтаксис

HTML-документ — текстовый файл (`.html`/`.htm`) со структурированным набором элементов, комментариев (`<!-- -->`) и пробельных символов.

```html
<!DOCTYPE HTML>
<html>
  <head><title>Sample of HTML</title></head>
  <body>
    <!-- comment -->
    <p>Simple text.</p>
  </body>
</html>
```

Элементы делятся на:
- **контейнеры** — открывающий тег, содержимое, закрывающий тег;
- **автономные / void-elements** (без содержимого и закрывающего тега): `area, base, br, col, embed, hr, img, input, keygen, link, menuitem, meta, param, source, track, wbr`.

Атрибуты пишут через пробел, значение — в кавычках (рекомендация стандарта — всегда). **Логический атрибут** — если указан (даже без значения или со значением, равным имени атрибута/пустой строке), значит «истина»; отсутствует — «ложь» (пример: `disabled`, `required`, `hidden`). Регистр имён тегов/атрибутов не важен (рекомендуется нижний), но значения атрибутов могут быть регистрозависимы.

**Спецсимволы**: `&имя;` или `&#код;` — например `&nbsp;` (неразрывный пробел), `&quot;` (`"`), `&lt;` (`<`), `&gt;` (`>`), `&copy;` (©).

### HTML vs XML / XHTML

| | HTML | XML |
|---|---|---|
| Регистр тегов | не важен | важен |
| Набор тегов | фиксированный | произвольный |
| Закрытие тегов | не все обязаны | все обязаны |
| Атрибуты | допускаются логические (без значения) | всегда `имя="значение"` |

**XHTML** — HTML, приведённый к правилам XML (все теги закрыты, нижний регистр, `атрибут="атрибут"` вместо логических атрибутов). *Где пригодится: если валидатор ругается на незакрытый тег или заглавные буквы в имени тега — это как раз конфликт между «вольным» HTML и строгостью XML/XHTML.*

### Глобальные атрибуты

Применимы к любому HTML-элементу.

| Атрибут | Назначение |
|---|---|
| `id` | уникальный идентификатор элемента в документе |
| `class` | одно/несколько имён класса через пробел |
| `style` | inline-CSS |
| `title` | всплывающая подсказка (tooltip) |
| `accesskey` | клавиша быстрого доступа (`Alt`+символ) |
| `tabindex` | позиция при переходе по `Tab` |
| `dir` | направление текста: `ltr`/`rtl`/`auto` |
| `lang` | язык содержимого элемента (влияет, например, на вид кавычек) |
| `hidden` (HTML5) | элемент не отображается |
| `contenteditable` (HTML5) | доступен для редактирования пользователем |
| `spellcheck` (HTML5) | проверка орфографии |
| `translate` (HTML5) | нужен ли перевод содержимого |
| `data-*` (HTML5) | произвольные пользовательские данные для JS, имя — только нижний регистр |
| `draggable`, `dropzone` | drag&drop |
| `itemscope`, `itemtype`, `itemprop`, `itemid`, `itemref` | микроданные (см. ниже) |

*Где пригодится: ЛР1 прямо требует «глобальные атрибуты» — значит нужно осознанно продемонстрировать хотя бы `id`, `class`, `title`, `lang`, `data-*`, `hidden`.*

**Глобальные атрибуты событий** — `on`+событие (`onclick`, `onchange`, `onsubmit`, `onmouseover`, `onload` и т.д.) — назначают обработчик JS прямо в разметке (подробнее — в ЛР3).

### Структура документа и метаданные

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Заголовок окна/вкладки</title>
  <meta name="description" content="Описание страницы">
  <meta name="keywords" content="ключевые, слова">
  <meta name="robots" content="index, follow">
  <link rel="stylesheet" href="styles.css">
  <link rel="shortcut icon" href="favicon.ico" type="image/x-icon">
  <base href="http://site.ru/" target="_blank">
</head>
<body>...</body>
</html>
```

- `<!DOCTYPE html>` — обязателен первым, сообщает браузеру версию стандарта; без него браузер уходит в «режим совместимости». *Где пригодится: без DOCTYPE валидатор W3C сразу выдаёт ошибку.*
- `<html lang="ru">` — корневой элемент, атрибут `lang` рекомендован.
- `<head>` — метаданные: обязателен единственный `<title>`; опциональны `base, meta, link, style, script, noscript`.
- `<meta charset="utf-8">` — должен быть в первых 512 байтах документа.
- `<meta http-equiv="refresh" content="5; url">` — настройка HTTP-заголовков через мета-тег (автообновление и т.п.).
- `<meta name="..." content="...">` — произвольные метаданные: `author`, `description`, `keywords`. *Где пригодится: ЛР1 явно требует метаданные для поисковых систем — `description`/`keywords`/`robots` покрывают это требование.*
- `<link rel="stylesheet">` — подключение CSS; `rel="shortcut icon"` — фавиконка (требование ЛР1).
- `<base href target>` — базовый адрес и целевое окно для всех относительных ссылок страницы.

**Микроданные (microdata, HTML5)** — атрибуты `itemscope`, `itemtype`, `itemprop` встраивают в разметку структурированные данные по словарю schema.org, которые понимают поисковые роботы:

```html
<div itemscope itemtype="http://schema.org/Product">
  <h1 itemprop="name">Кроссовки Nike Air</h1>
  <span itemprop="price">120</span> BYN
  <img itemprop="image" src="shoe.jpg" alt="Кроссовки">
</div>
```
*Где пригодится: это и есть «микроданные для поисковых систем» из явного требования ЛР1 — накрыть карточку товара/статьи микроразметкой schema.org (Product, Article, Organization).*

## 2. Семантическое и шрифтовое выделение текста

| Элемент | Визуально | Семантически |
|---|---|---|
| `<b>` | жирный | привлечение внимания (ключевые слова) |
| `<strong>` | жирный акцент | важность текста |
| `<em>` (emphasis — акцент) | курсив | логическое ударение |
| `<i>` | курсив | иностранные слова, термины |
| `<s>` | зачёркнутый | неактуальное содержимое |
| `<u>` | подчёркнутый | устарел в HTML5 |
| `<small>` | мельче на 1 размер | «мелкий шрифт» (оговорки) |
| `<sub>`/`<sup>` | нижний/верхний индекс | то же |
| `<mark>` (HTML5) | жёлтый фон | выделенный текст |

Эти элементы — контейнерные, строчные (не блочные), можно вкладывать друг в друга: `<i>курсив<b>жирный курсив</b></i>`.

**Листинг кода**: `code` (моноширинный шрифт кода), `var` (переменная, курсив), `samp` (вывод программы), `kbd` (ввод пользователя).
```html
<code>var x = 5;</code> — <var>x</var> — результат: <samp>5</samp>, ввёл: <kbd>5</kbd>
```
*Где пригодится: ЛР1 прямо требует «пример листинга» — это про `<code>/<var>/<samp>/<kbd>`.*

**Сокращения**: `<abbr title="расшифровка">FDOC</abbr>` — визуально пунктирное подчёркивание.

**Определения**: `<dfn title="термин">термин</dfn>` — обычно курсивом. Также есть список определений `<dl>` (см. ниже).

**Цитаты**: `<q cite="url">строчная цитата в кавычках</q>`, `<blockquote cite="url">блочная цитата с отступами</blockquote>`, `<cite>` — источник цитаты курсивом. *Где пригодится: ЛР1 требует «пример цитат» — используйте `q` и `blockquote` с `cite`.*

**Дата/время**: `<time datetime="2024-12-31T19:00">31 декабря</time>` — машиночитаемая дата/время. *Прямое требование ЛР1 «дата-время».*

**Выделенный текст**: `<mark>текст</mark>` — жёлтый фон.

**Произвольный интервал**: `<span>` (англ. «span» — участок, промежуток) — строчный контейнер-аналог `div`, только для CSS-стилизации фрагмента.

**Перевод строки**: `<br>` — фиксированный перенос; `<wbr>` — место **потенциального** переноса, если не влезает по ширине. *Где пригодится: ЛР1 явно требует «текст в виде четверостишия с фиксированным и потенциальным переводом строки» — это `<br>` (стихи) + `<wbr>` (например, в длинном слове/URL).*

```html
<p>
  Мело, мело по всей земле<br>
  Во все пределы.<br>
  Свеча горела на столе,<br>
  Свеча горела.<wbr>— Пастернак
</p>
```

`<font>` — устаревший визуальный контейнер шрифта (`color`, `face`, `size`), заменяется CSS — не использовать.

### Ссылки и якоря

```html
<a href="http://mail.ru">переход</a>
<a href="mailto:user@site.by?subject=Вопрос">email-ссылка</a>
<a href="tel:+375291112233">телефонная ссылка</a>
<a href="report.pdf" download="Отчёт.pdf">скачать документ</a>
<a href="#section2">Якорь на #section2 в этом документе</a>
<h2 id="section2">Раздел 2</h2>
```
- `href` — адрес; содержимым может быть `img` (уберите синюю рамку через CSS, а не `border="0"`).
- `download` (HTML5, логический/со значением) — не переход, а скачивание файла.
- `target="_blank"` — открыть в новой вкладке; `rel="nofollow"` — не передавать ссылочный вес.
- Якорь — либо старый `<a name="n1">`, либо (в HTML5) переход по `id` любого элемента: `<a href="#n1">` → `<p id="n1">`.

*Где пригодится: ЛР1 требует «ссылки разного вида, в т.ч. для скачивания документа» и «якоря» — используйте связку из примера выше (обычная, mailto/tel, download, якорь).*

### Группировка контента (блочные элементы)

`div, p, pre, blockquote, hr, ol, ul, dl, figure` — блочные: занимают всю ширину, начинаются с новой строки.

- `<div>` (сокращение от англ. division — «раздел») — универсальный блочный контейнер (аналог `span`, только блочный).
- `<p>` — абзац (не может содержать другой `<p>`).
- `<pre>` — предварительно форматированный текст (моноширинный шрифт, сохраняет пробелы/переносы).
- `<hr>` — тематический разрыв (горизонтальная линия).
- Списки: `<ul>` (маркированный), `<ol>` (нумерованный, атрибуты `start`, `reversed`), пункт — `<li>`.
- **Список определений**: `<dl><dt>термин</dt><dd>определение</dd></dl>` — глоссарий/FAQ. *Где пригодится: ЛР1 — раздел «Словарь терминов» идеально ложится на `dl/dt/dd`.*
- **Фигура**: `<figure><img src="..."><figcaption>подпись</figcaption></figure>` — логически неделимый блок «картинка + подпись» (`figcaption` — первым или последним). *Прямое требование ЛР1 «фигуры».*

### Семантические секции HTML5

| Элемент | Назначение |
|---|---|
| `h1`–`h6` | заголовки уровней; `hgroup` — группа заголовков |
| `header` / `footer` | «шапка»/«подвал» страницы или секции (не вкладываются друг в друга и в `address`) |
| `nav` (navigation — навигация) | блок навигации (меню ссылок) |
| `main` | основной уникальный контент страницы (по HTML5.1 — не более одного на документ) |
| `section` | тематически сгруппированный контент, обычно с заголовком |
| `article` | самодостаточный контент (новость, пост, статья) — может быть внутри `section` или содержать `section` |
| `aside` (aside — «в стороне») | «сайдбар» — контент сбоку от основного (рубрики, ссылки на архив) |
| `address` | контактная информация автора страницы (курсивом по умолчанию) |
| `details`/`summary` | сворачиваемый блок: `summary` — заголовок, `open` — атрибут начального состояния |

```html
<body>
  <header><h1>Название компании</h1><nav>...меню...</nav></header>
  <main>
    <section>
      <article><h2>Новость 1</h2><p>Текст...</p></article>
    </section>
    <aside>Похожие статьи</aside>
  </main>
  <footer>Copyright</footer>
</body>
```

*Где пригодится: это и есть требование ЛР1 «семантическая вёрстка» и «навигация горизонтальная/вертикальная» — `nav` для главного горизонтального меню сверху и `aside`/боковой `nav` для вертикального; каждая карточка новости — `article` внутри `section`.*

Инструмент проверки структуры заголовков/секций — HTML5 Outliner.

### Таблицы

```html
<table>
  <caption>Заголовок таблицы</caption>
  <colgroup><col style="width:30%"><col></colgroup>
  <thead>
    <tr><th id="name">Товар</th><th id="price">Цена</th></tr>
  </thead>
  <tbody>
    <tr><td headers="name">Кофе</td><td headers="price">10</td></tr>
    <tr><td colspan="2">Итого: 10 BYN</td></tr>
  </tbody>
  <tfoot><tr><td colspan="2">Обновлено сегодня</td></tr></tfoot>
</table>
```

- `table > caption?, colgroup*, thead?, (tbody* | tr+), tfoot?` — порядок вложенности задан спецификацией; браузер сам достраивает неявный `tbody`.
- `th` — заголовочная ячейка, `td` — обычная.
- `colspan`/`rowspan` — объединение ячеек по горизонтали/вертикали (заполнение «слева направо, сверху вниз», ячейка «вытесняется»).
- `headers="id1 id2"` у `td` — связь ячейки данных с заголовочными ячейками по их `id` (для скринридеров). **Именно этот атрибут ЛР1 требует «не использовать для вёрстки, только для данных».**
- Устаревшие атрибуты (`border`, `bgcolor`, `align`, `cellpadding`, `cellspacing`, `width` у `table/tr/td`) — заменяются CSS в ЛР2.

*Где пригодится: ЛР1 требует таблицу «с заголовочными ячейками, цифровыми и текстовыми данными, объединёнными ячейками, атрибутом headers» — используйте пример выше как каркас (например, для каталога/прайса).*

```html
<form action="/submit" method="post" enctype="multipart/form-data" novalidate autocomplete="on">
  <fieldset>
    <legend>Регистрация</legend>
    <label for="email">Email:</label>

    <input type="range" name="vol" min="0" max="100">

    <input type="file" name="avatar" accept="image/*" multiple>

```

- **Метод передачи**: `GET` — данные в URL (URL — Uniform Resource Locator, адрес ресурса в интернете; видны, ограничены по длине); `POST` — в теле запроса. `enctype`: `application/x-www-form-urlencoded` (по умолчанию), `multipart/form-data` (обязателен при загрузке файлов), `text/plain`.
- **Атрибуты `form`**: `action`, `method`, `name`, `target`, `autocomplete`, `novalidate` (отключает встроенную валидацию браузера).
- **Типы `input`** (классические): `text, password, radio, checkbox, hidden, file, button, submit, reset, image`.
- **Новые типы HTML5**: `color, date, datetime-local, email, number, range, search, tel, time, url, month, week`.
- **Атрибуты валидации**: `required`, `pattern` (regexp), `min`/`max`/`step` (числа/даты/range), `maxlength`/`minlength`, `readonly` (значение видно, но не редактируется и передаётся), `disabled` (не редактируется и **не** передаётся на сервер).
- `placeholder` — подсказка внутри поля, `autofocus` — фокус при загрузке.
- `select` + `option` (`selected`, `disabled`, `value`, `label`) + `optgroup` (визуальная группа) + `datalist` (подсказки для `input list="id"`).
- `button` — контейнер-кнопка с произвольным содержимым (`type="button|submit|reset"`).
- `fieldset`+`legend` — группировка полей с подписью и общей блокировкой (`disabled` у fieldset).
- `label` — связь подписи с полем: через `for="id"` либо вложением поля внутрь `label`. *Где пригодится: улучшает доступность и требуется по факту «элементы управления... включая валидацию».*

*Где пригодится: ЛР1 требует «разные виды input, выпадающие списки, контейнеры, кнопки, включая валидацию» — приведённая форма покрывает все типы разом; можно взять её как шаблон для формы отзыва/регистрации/заказа.*

### `iframe`

`iframe` (сокращение от inline frame — «встроенный кадр») — встраивает внутрь текущей страницы содержимое другого HTML-документа (карту, видео, другой сайт) как отдельное вложенное окно.

```html
        sandbox="allow-scripts allow-same-origin" title="Карта">

```
`sandbox` — «песочница», ограничивает возможности встроенного документа (`allow-forms`, `allow-scripts`, `allow-same-origin`, `allow-top-navigation`). *Где пригодится: ЛР1 требует iframe — уместно для карты проезда на странице «Контакты» или встраивания видео с внешнего сервиса.*

### Изображения

```html
<img src="logo.png" alt="Логотип компании" width="200" height="100">

<!-- адаптивное изображение по плотности пикселей -->
<img src="low.jpg" srcset="low.jpg 1x, high.jpg 2x, ultra.jpg 3x" alt="...">

<!-- адаптивное изображение по ширине окна -->
<img src="low.jpg" sizes="(max-width: 40em) 100vw, 50vw"
     srcset="low.jpg 600w, high.jpg 1000w, ultra.jpg 1400w" alt="...">

<!-- разные картинки/форматы под разные условия -->
<picture>
  <source media="(max-width: 600px)" srcset="banner-mobile.jpg">
  <source type="image/webp" srcset="banner.webp">
  <img src="banner.jpg" alt="Баннер">
</picture>
```
`src` и `alt` — обязательны (`alt` — для скринридеров, при отключенных картинках, при ошибке загрузки). `srcset`/`sizes`/`picture` — подключение разных изображений под разные экраны/плотности пикселей — это и есть требуемая «адаптивность» (бонус в ЛР1).

## 1. Общие сведения о CSS

**CSS (Cascading Style Sheets)** — язык описания внешнего вида документа, созданного языком разметки (обычно HTML). *Цель — отделить структуру документа от оформления.*

История: 1994 — Хокон Виум Ли; 1996 — CSS1; 1998 — CSS2; 2011 — CSS2.1; CSS3 — модульный стандарт (разные модули развиваются с разной скоростью), CSS4 — в разработке.

### Синтаксис

```css
/* комментарий */
селектор1, селектор2 {
  свойство: значение; /* объявление */
  свойство2: значение2 !important; /* максимальный приоритет */
}
```
**Значения свойств**: ключевое слово, число, проценты, размер, цвет, URL (`url()`), строка, временной промежуток (`s`/`ms`), угол (`deg`/`rad`/`grad`/`turn`).

**Единицы размера**:
- абсолютные — `cm, mm, in, pt (1pt=1/72in), pc`;
- относительные — `px` (1/96 дюйма), `em` (размер шрифта элемента), `rem` (размер шрифта корневого `<html>`), `ex`, `%` (от значения родителя), `vw`/`vh` (1% ширины/высоты окна).

**Цвет**: имя (`red`), hex (`#RRGGBB`/`#RGB`), функции `rgb()`, `rgba()`, `hsl()`, `hsla()`.

### Подключение CSS

```html
<link rel="stylesheet" href="mystyle.css">           <!-- 1. внешний файл -->
<style>@import url(style.css);</style>                <!-- 2. импорт внутри style -->
<style>body { color: red; }</style>                   <!-- 3. блок style в head -->
<p style="font-size: 20px; color: green">...</p>      <!-- 4. inline на элементе -->
```
`@charset "utf-8";` — кодировка CSS-файла (первая строка файла). `@import` — только сразу после `@charset`/других `@import`.

### Селекторы

| Селектор | Что выбирает |
|---|---|
| `*` | все элементы |
| `p` | элемент по тегу |
| `.main` | по классу |
| `#pass` | по `id` |
| `[attr]` | элемент, имеющий атрибут (любое значение) |
| `[attr="val"]` | атрибут равен значению |
| `[attr^="val"]` | значение **начинается** с подстроки |
| `[attr$="val"]` | значение **заканчивается** подстрокой |
| `[attr*="val"]` | значение **содержит** подстроку |
| `[attr~="val"]` | одно из значений в списке через пробел |
| `[attr\|="val"]` | значение или начинается с `val-` |
| `p.main` | AND (элемент **и** класс) |
| `div p` | селектор потомков (на любом уровне) |
| `div > p` | селектор дочерних (только прямые дети) |
| `h1 + p` | соседний следующий элемент |
| `h1 ~ p` | все следующие «братья» |

*Где пригодится: ЛР2 прямо требует селекторы атрибутов `^=`/`$=`/`=`, классов и комбинации потомок/дочерний — типичный пример: `a[href^="http://"]{font-weight:bold}` для внешних ссылок, `a[href$=".ru"]` — иконка по домену.*

### Псевдоклассы

**Состояние ссылок/фокуса** (порядок в CSS важен — LVHA): `:link` → `:visited` → `:hover` → `:active`; ещё `:focus`.
```css
a:link{color:blue} a:visited{color:purple} a:hover{color:red} a:active{color:orange}
.form-input:focus{border-color:blue;outline:none}
```

**Структурные**: `:first-child`, `:last-child`, `:only-child`, `:nth-child(n)` (в т.ч. `odd`/`even`/`3n`/`3n+1`), `:nth-of-type(n)`, `:first-of-type`, `:root`.
```css
li:nth-child(odd){background:gold}
tr:nth-child(even){background:#eef}
```

**UI/форма**: `:enabled`, `:disabled`, `:checked`, `:required`, `:optional`, `:valid`, `:invalid`, `:in-range`, `:out-of-range`, `:default`.
```css
input:invalid{border:2px solid red;background:#fdd}
input:required{border-left:3px solid orange}
input:disabled{opacity:.5}
input:checked + label{font-weight:bold}
```
*Где пригодится: прямое требование ЛР2 — «выделить доступные, обязательные, заблокированные элементы, значения вне диапазона, включённые флажки» — набор селекторов выше.*

**Прочие**: `:not(селектор)`, `:empty`, `:lang(код)`, `:target`.
```css
q:lang(fr), q:lang(ru) { quotes: "«" "»"; }
q:lang(en) { quotes: "\201C" "\201D"; }
```
*Где пригодится: прямое требование ЛР2 — «отображение кавычек в зависимости от языка цитаты» — `:lang()` + свойство `quotes`.*

### Псевдоэлементы

```css
p::first-letter{font-size:200%;color:red}     /* первая буква абзаца статьи */
p::first-line{font-style:italic}               /* первая строка */
a::before{content:"Ссылка: "}                    /* контекст перед элементом */
a::after{content:" →"}                           /* контекст после элемента */
::selection{background:yellow}                   /* при выделении текста */
li{list-style:none}
li::before{content:"\20aa ";}                    /* маркер — символ юникода */
```
*Где пригодится: всё это — прямые требования ЛР2 (первая буква абзаца статьи, контекст в начале/конце текста, маркеры-юникод, стиль выделения).*

### Наследование и каскадирование

**Наследование** — часть свойств (в основном текстовые: `color`, `font-*`, `line-height`, `text-*`) передаётся от родителя к потомку автоматически; блочные (`border`, `margin`, `padding`) — не наследуются. Форсировать: `свойство: inherit;`.

**Каскадирование** — порядок применения: Default CSS браузера → User CSS → Author CSS → Author CSS `!important` → User CSS `!important`.

**Вес правила (специфичность)** — четвёрка `(inline, id, class/attr/pseudo-class, element/pseudo-element)`:

| Селектор | (a,id,c,e) |
|---|---|
| `*` | 0,0,0,0 |
| `li` | 0,0,0,1 |
| `ul li` | 0,0,0,2 |
| `li.red` | 0,0,1,1 |
| `#abc` | 0,1,0,0 |
| `style="..."` | 1,0,0,0 |

Сравнение — слева направо; при равенстве весов побеждает правило, объявленное позже в файле. *Где пригодится: классический баг вёрстки «стиль не применяется» почти всегда решается через понимание специфичности — прежде чем ставить `!important`, проверьте вес селектора.*

## 2. Блочная модель, фон, градиенты, позиционирование

### Box model

```
┌───────────────margin───────────────┐
│ ┌─────────────border────────────┐  │
│ │ ┌───────────padding─────────┐ │  │
│ │ │        content            │ │  │
│ │ └────────────────────────────┘ │ │
│ └────────────────────────────────┘ │
└──────────────────────────────────────┘
```
Итоговая ширина блока по умолчанию = `margin + border + padding + width` (алгоритм `content-box`). Свойство `box-sizing: border-box` меняет расчёт: `width`/`height` уже **включают** `padding` и `border` — удобнее при вёрстке сеток. *Где пригодится: `box-sizing: border-box` — стандартная практика реальной вёрстки, полезно для карточек товара в каталоге ЛР1/ЛР2.*

**Схлопывание вертикальных margin** (margin collapsing) — у двух соседних блоков по вертикали берётся не сумма, а бо́льшее значение отступа; не работает для `float`, `absolute`, inline, при наличии `padding`/`border` со стороны схлопывания.

**Граница**: `border-width|style|color`, форма — `border: 2px solid red;` (можно сокращённо задать все 4 стороны, 2 значения — верх/низ и лево/право, 3 или 4 отдельных значения). Стили линии: `none, dotted, dashed, solid, double, groove, ridge, inset, outset`.

**Скругление углов**: `border-radius: 50px 0 0 50px;` — 1/2/3/4 значения по углам (по часовой с верхнего левого); через `/` — раздельные радиусы для эллипса. Круглая картинка: `border-radius: 50%`. *Где пригодится: прямое требование ЛР2 — «круглые блоки для партнёров».*

**Изображение вместо границы**: `border-image: url(bg.png) 30 round round;` (+ вендорные префиксы `-moz-`, `-webkit-`, `-o-` для старых браузеров). *Прямое требование ЛР2 для сертификата.*

**outline** — рамка вне модели блока, не влияет на ширину/высоту (в отличие от `border`): `outline: thick solid red; outline-offset: -10px;`

### Фон

```css
body {
  background-color: #f0f0f0;
  background-image: url(bg.jpg);
  background-repeat: no-repeat;       /* repeat | repeat-x | repeat-y | no-repeat */
  background-position: center bottom; /* left/center/right top/center/bottom | % | размер */
  background-size: cover;             /* cover | contain | размер | % */
  background-attachment: fixed;       /* fixed — не скроллится вместе с контентом */
  background-clip: border-box;        /* padding-box | border-box | content-box */
  background-origin: content-box;
}
```
Сокращённая форма: `background: color image position/size repeat attachment;`

### Градиенты

```css
.grd { background: linear-gradient(to right, red, blue); }
.grd2 { background: linear-gradient(110deg, red 0%, blue 50%, white 100%); }
.grd3 { background: radial-gradient(circle at 30px 20px, red, blue); }
.grd4 { background: repeating-linear-gradient(red, blue 20px, red 40px); }
```
`linear-gradient(угол|направление, цвет1 [позиция], ...)`, `radial-gradient([circle|ellipse] [размер] [at позиция], ...)`. Размер круга: `closest-side | closest-corner | farthest-side | farthest-corner`. Есть `repeating-linear-gradient()`/`repeating-radial-gradient()`. *Прямое требование ЛР2 для сертификата — градиент фона.*

**Тень блока**: `box-shadow: <x> <y> <blur> <spread> <color>;` (можно несколько теней через запятую). **Тень текста**: `text-shadow: <x> <y> <blur> <color>;`.

### Отступы, размер, позиционирование

`padding`/`margin` — 1/2/3/4 значения (аналогично `border-width`); `margin: auto` центрирует блок с заданной шириной. `overflow: visible|hidden|scroll|auto` — поведение содержимого, не помещающегося в блок; `min/max-width/height` — ограничения при резиновой вёрстке.

`display`: `none` (не отображается и не занимает место), `block`, `inline`, `inline-block` (блочная модель + строчное расположение), `list-item`.

`visibility: hidden` — элемент невидим, но **место сохраняется** (в отличие от `display:none`).

**position**:

| Значение | Относительно чего смещается | Убирается из потока? |
|---|---|---|
| `static` (по умолч.) | обычное размещение в потоке | нет |
| `relative` | своей исходной позиции | нет (место резервируется) |
| `absolute` | ближайшего предка с `position` ≠ `static` (иначе — окно) | да |
| `fixed` | окна браузера, не скроллится | да |
| `sticky` | ведёт себя как `relative`, пока не пересечёт порог — затем «прилипает» как `fixed` | нет |

`top/right/bottom/left` — смещение при непозиционировании `static`. `z-index` — порядок наложения (работает только для позиционированных элементов). *Где пригодится: прямое требование ЛР2 — «инфо о последней статье — через position» и «область навигации фиксируется при прокрутке» → `position: sticky` (или `fixed`) для навигации.*

**Плавающие блоки**: `float: left|right|none;` — элемент «прижимается» к краю, остальной контент обтекает; `clear: left|right|both;` — запрещает соседство с плавающими блоками с указанной стороны. *Прямое требование ЛР2 для «Вакансий».*

### Трансформации и переходы (transition), анимация

```css
.logo { transform: rotate(-15deg) scale(1.2); transform-origin: left top; }
```
Функции: `rotate(угол)`, `scale(n)`/`scaleX`/`scaleY`, `translate(x,y)`/`translateX`/`translateY`, `skew(x,y)`/`skewX`/`skewY`, `matrix(a,b,c,d,e,f)`. `transform-origin` меняет точку отсчёта преобразования. *Прямое требование ЛР2 — трансформация логотипа.*

```css
div { transition: width 2s ease 100ms, background 0s 4s; }
div:hover { width: 100%; }
```
`transition-property | -duration | -timing-function (ease, linear, ease-in, ease-out, ease-in-out, cubic-bezier()) | -delay`.

```css
@keyframes slide {
  0%   { left: 0; }
  50%  { left: 244px; top: 100px; }
  100% { left: 488px; top: 0; }
}
.ball { animation: slide 2s ease-in-out infinite alternate; }
```
`animation-name | -duration | -delay | -timing-function | -iteration-count (число|infinite) | -direction (normal|alternate|reverse|alternate-reverse) | -fill-mode (none|forwards|backwards|both) | -play-state (running|paused)`.

*Где пригодится: прямое требование ЛР2 — «анимация на главной странице сайта» по своему варианту (см. таблицу выше) и «прелоадер». Прелоадер обычно — вращающийся круг через `@keyframes rotate {to{transform:rotate(360deg)}}` + `animation: rotate 1s linear infinite;`.*

## 3. Текст, списки, таблицы

### Текст

| Свойство | Назначение |
|---|---|
| `text-align` | `left/right/center/justify` |
| `text-indent` | красная строка (размер/%) |
| `line-height` | межстрочный интервал |
| `letter-spacing` / `word-spacing` | интервал между символами/словами |
| `white-space` | `normal/nowrap/pre/pre-line/pre-wrap` — обработка пробелов/переносов |
| `word-wrap`/`word-break` | перенос длинных слов (`break-word`, `break-all`) |
| `text-overflow: ellipsis` | многоточие при обрезке (нужен `overflow:hidden` + `white-space:nowrap`) |
| `text-decoration` | `underline / overline / line-through / none` |
| `text-transform` | `capitalize / uppercase / lowercase / none` |
| `font-kerning` | попарная подгонка ширины символов |
| `font-variant: small-caps` | капитель |

```css
.news-preview {
  overflow: hidden; white-space: nowrap; text-overflow: ellipsis;
}
.article-body { columns: 2; column-gap: 30px; column-rule: 1px solid #ccc; }
```
*Где пригодится: прямые требования ЛР2 — «overflow + многоточие для краткого содержания статьи» и «многоколоночный макет для полного текста статьи» — код выше решает оба пункта.*

### Шрифты

```css
@font-face {
  font-family: "Roboto";
  src: url("/fonts/Roboto-Regular.woff2") format("woff2");
  font-weight: normal; font-style: normal;
}
body { font-family: "Roboto", Arial, sans-serif; }
```
Свойства: `font-family` (список через запятую — «font stack», в конце — родовое семейство `serif/sans-serif/monospace/cursive/fantasy`), `font-size`, `font-style` (`normal/italic/oblique`), `font-weight` (100–900, `normal`=400, `bold`=700), `font-variant`. Подключение внешних шрифтов — своё правило `@font-face` либо сервис Google Fonts (`<link>` или `@import`). *Прямое требование ЛР2 — «основной шрифт из службы шрифтов + альтернативный + семейство».*

### Списки

```css
ul { list-style: square inside; }              /* тип + положение маркера */
ol { list-style-type: lower-roman; }
li { list-style-image: url(marker.png); }
li::before { content: "\2605 "; }                /* маркер — символ юникода через псевдоэлемент */
```
`list-style-type` (`disc, circle, square, decimal, lower-roman, ...`), `list-style-position` (`inside`/`outside`), `list-style-image`.

### Таблицы

```css
table { border-collapse: collapse; width: 100%; margin: 0 auto; }
caption { caption-side: top; font-weight: bold; padding-bottom: 10px; }
td, th { border: 1px solid #ccc; padding: 8px; text-align: center; vertical-align: middle; }
td:empty { background: #f5f5f5; }
tr:nth-child(even) { background: #f9f9f9; }
tbody tr:hover { background: khaki; }
```
- `border-collapse: collapse` — убирает двойные линии между ячейками (по умолч. `separate`).
- `empty-cells: hide|show` — фон/видимость пустых ячеек.
- `caption-side: top|bottom` — положение заголовка таблицы.
- `text-align`/`vertical-align` — гор./верт. выравнивание содержимого ячеек.
- `table-layout: fixed` — быстрый алгоритм разметки (ширина по столбцам, а не по содержимому — полезно для больших таблиц).

*Где пригодится: весь этот блок — прямые требования ЛР2 к таблицам (двойные линии, фон пустых ячеек, заголовок над таблицей, выравнивание, стилизация строк/столбцов).*

## 4. Flexbox, Grid, колонки, медиа-запросы

### Flexbox

```css
.flex-container {
  display: flex;                 /* или inline-flex */
  flex-direction: row;           /* row | row-reverse | column | column-reverse */
  flex-wrap: wrap;                /* nowrap | wrap | wrap-reverse */
  justify-content: space-between; /* выравнивание по главной оси */
  align-items: center;            /* выравнивание по поперечной оси */
  gap: 16px;
}
.flex-item { flex: 1 1 200px; order: 2; align-self: flex-start; }
```
`justify-content`: `flex-start | flex-end | center | space-between | space-around`. `align-items`/`align-self`: `stretch | flex-start | flex-end | center | baseline`. `flex: рост сжатие базовый-размер` (сокращённая форма `flex-grow/flex-shrink/flex-basis`).

*Где пригодится: прямое требование ЛР2 — «Контакты: Flexbox для карточек сотрудников» — каждая карточка `.flex-item` внутри `.flex-container{display:flex; flex-wrap:wrap; gap:20px}`.*

### CSS Grid Layout

```css
.grid-container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-template-rows: auto;
  gap: 20px;
}
.item-wide { grid-column: 1 / 3; }   /* объединить 2 колонки */
```
`grid-template-columns`/`-rows` — размер колонок/строк (значения через пробел, `fr` — «доля» свободного пространства); `grid-template-areas` — именованная раскладка через строки-шаблоны; `grid-gap`/`gap` — зазор; `grid-column-start/end`, `grid-row-start/end` — позиционирование элемента.

*Где пригодится: прямое требование ЛР2 — «отображение каталога товаров через CSS Grid» — каждая карточка товара = элемент сетки `.grid-container{display:grid;grid-template-columns:repeat(auto-fill,minmax(220px,1fr));gap:20px}`.*

### Многоколоночный текст

```css
.article { columns: 200px 3; column-gap: 30px; column-rule: 1px solid #ddd; }
```
`column-width`/`column-count`/`columns` (сокращённая форма); `column-rule` — разделительная линия; `column-span: all` — заголовок на всю ширину; `break-inside: avoid` — запрет разрыва блока между колонками.

### Медиа-запросы

```css
@media screen and (max-width: 768px) {
  .grid-container { grid-template-columns: 1fr; }
}
@media (orientation: landscape) { ... }
```
Синтаксис: `@media [тип] and (условие) { правила }`. Типы: `all, screen, print, speech`. Логика: `and` (И), `,` (ИЛИ), `not` (НЕ, применяется ко всему выражению целиком). Функции: `width/min-width/max-width`, `height/min-height/max-height`, `orientation`, `aspect-ratio`, `color`. *Прямое требование ЛР2 — «медиа-запросы для отображения по ширине/высоте области».*

### Прочее

`cursor: pointer;` — вид курсора над кнопками (прямое требование ЛР2). `calc()` — вычисление с разными единицами: `width: calc(100% - 80px);`. `filter: blur(5px) brightness(120%);` — визуальные фильтры.

## 1. Основы языка JavaScript

**JavaScript** — прототипно-ориентированный сценарный язык программирования (создан Бренданом Айком в Netscape в 1995 году). Стандартизирован как **ECMAScript** (ECMA-262); версии называют ES5 (2009), ES6/ES2015, далее — по годам (ES2016, ..., ES2024 ежегодно). *Где пригодится: когда преподаватель спросит «а почему `let` лучше `var`» — это как раз про ES6, который поддерживают все современные движки (V8 в Chrome, SpiderMonkey в Firefox и т.д.).*

Подключение скрипта:
```html
<script src="scripts/app.js" defer></script>  <!-- выполнится после парсинга HTML, порядок сохранён -->
<script src="counter.js" async></script>       <!-- выполнится сразу по загрузке, порядок не важен -->
```
`defer` — для скриптов, которым нужен весь DOM (DOM — Document Object Model, дерево объектов, в которое браузер превращает HTML-документ; подробно — в разделе 2 ниже) и важен порядок относительно друг друга; `async` — для независимых скриптов (счётчики, реклама).

### Лексика и типы

Инструкции разделяются `;` (JS умеет автоматически вставлять точку с запятой — ASI, но полагаться на это не стоит). Идентификаторы: буквы, цифры, `_`, `$`, не с цифры. `"use strict";` в начале файла/функции — строгий режим (запрещает необъявленные переменные, неоднозначности и т.п.). *Где пригодится: строгий режим ловит опечатки вида `usrName = 5` (без `var/let`) ещё на этапе разработки — обязательно включайте в ЛР3.*

**Типы данных**: `number`, `string`, `boolean`, `null`, `undefined`, `symbol` (ES6), `object` (включает массивы и функции). Оператор `typeof x` — возвращает тип строкой (`typeof null === "object"` — историческая особенность).

```js
var x = 10;        // область видимости — функция, "поднимается" (hoisting)
let y = 20;         // область видимости — блок {}
const PI = 3.14;    // константа-ссылка (объект по ссылке можно мутировать!)
```
*Где пригодится: в ЛР3 и ЛР4 используйте `let`/`const` — это ожидаемый современный стиль.*

**Приведение типов** — JS слабо типизирован, преобразует автоматически:
```js
"37" - 7      // 30 (к числу)
"37" + 7      // "377" (конкатенация строк — если хоть один операнд строка, "+" склеивает)
+"123"        // 123 (унарный плюс — быстрый способ привести к числу)
Number("1.2e2")   // 120
parseInt("123px") // 123 (гибкий разбор, отбрасывает "хвост")
Boolean(0), Boolean(""), Boolean(null), Boolean(undefined), Boolean(NaN) // всегда false
!!value       // двойное отрицание — быстрое приведение к boolean
```
Ложные значения (falsy): `false, 0, "", null, undefined, NaN`. Все объекты, даже пустые `{}`/`[]`, — всегда `true`.

**Сравнение**: `===`/`!==` — строгое (без приведения типов), `==`/`!=` — нестрогое (с приведением). *Где пригодится: правило хорошего тона — всегда использовать `===`, чтобы не ловить баги вида `"" == false // true`.*

### Выражения и операторы

Арифметика: `+ - * / %`; инкремент/декремент `++x`/`x++` (различие — возвращаемое значение **до**/**после** изменения). Присваивание с операцией: `+= -= *= /= %=`. Логические: `&&` (И, возвращает первое ложное значение или последнее), `||` (ИЛИ, возвращает первое истинное или последнее — классический способ задать значение по умолчанию до ES6: `var x = a || 10;`), `!` (НЕ). Тернарный оператор: `cond ? a : b`. `typeof`, `instanceof`, `in`, `delete`, `void`, запятая `,`.

Взаимодействие с пользователем: `alert(msg)`, `prompt(msg, default)` (возвращает строку или `null`), `confirm(msg)` (возвращает `true`/`false`).

### Управляющие конструкции

```js
if (age >= 18) { ... } else if (...) { ... } else { ... }

switch (a) {
  case 1: ...; break;
  case 2:
  case 3: ...; break;   // группировка case
  default: ...;
}

for (let i = 0; i < arr.length; i++) { ... }
for (let key in obj) { ... }      // перебор имён свойств (в т.ч. унаследованных!)
for (let val of arr) { ... }      // перебор значений итерируемого объекта (массив, строка, Map, Set)
while (cond) { ... }
do { ... } while (cond);

outer: for (...) { for (...) { if (...) break outer; } }  // метка для break/continue
```
*Где пригодится: `for...of` — стандартный способ перебора массива в ЛР3 (таблица сотрудников, слайдер, каталог); `for...in` — для перебора свойств объекта (например, ключей конфигурации слайдера).*

### Функции

```js
function sum(a, b) { return a + b; }              // Function Declaration — «поднимается» целиком
var mul = function(a, b) { return a * b; };        // Function Expression — не поднимается
const sq = x => x * x;                             // стрелочная функция, краткая форма
const add = (a, b) => { return a + b; };            // блочная форма
function greet(name = "Гость") { alert(`Привет, ${name}`); }  // параметр по умолчанию
function sumAll(...nums) { return nums.reduce((s, n) => s + n, 0); }  // rest-параметры (собирают все переданные аргументы в один массив)
```
**Стрелочные функции**: не имеют собственного `this`/`arguments` — берут их из внешнего (лексического) окружения; нельзя использовать как конструктор (`new`). *Где пригодится: стрелочные функции — must have для обработчиков в методах объектов/классов в ЛР3 п.8 и в React-компонентах ЛР4, потому что не «теряют» `this`.*

**Область видимости и замыкание**: функция «видит» переменные внешнего кода на момент своего создания (замыкание — комбинация функции и её лексического окружения).
```js
function counter() {
  let n = 0;
  return () => ++n;    // замыкание хранит n между вызовами
}
const c = counter();
c(); c(); // 1, 2
```
*Где пригодится: замыкания — основа счётчиков слайдов в слайдере ЛР3 (например, текущий индекс слайда, скрытый внутри модуля) и хуков (hook — специальная функция React с именем `use...`, позволяющая функциональным компонентам хранить состояние и использовать другие возможности React; подробно — в разделе React, ЛР4) `useState` в ЛР4.*

**Контекст вызова (`this`)**: определяется способом вызова, а не местом объявления. `obj.method()` → `this === obj`. Простой вызов функции в нестрогом режиме → `this === window`, в строгом → `undefined`. Фиксация контекста: `func.call(ctx, a, b)`, `func.apply(ctx, [a,b])`, `func.bind(ctx)` (возвращает новую функцию с зафиксированным `this`).

**Немедленно вызываемая функция (IIFE)**:
```js
(function () { /* приватная область видимости */ })();
```

### Исключения

```js
try {
  if (amount < 0) throw new Error("Значение должно быть положительным");
} catch (e) {
  console.log(e.name, e.message);
} finally {
  hidePreloader();  // выполняется всегда
}
```
Встроенные конструкторы ошибок: `Error, SyntaxError, TypeError, RangeError, ReferenceError, URIError`. Глобальный перехват необработанных ошибок — `window.onerror`. *Где пригодится: прямое требование ЛР3 — валидация URL/телефона должна не просто игнорировать ошибку, а явно её обрабатывать (`try/catch` + подсветка поля).*

### Массивы

```js
let arr = [1, "два", [3]];
arr.push(4); arr.pop();                  // добавить/убрать с конца
arr.unshift(0); arr.shift();             // добавить/убрать с начала
arr.splice(1, 2, "a", "b");               // удалить 2 элемента с индекса 1, вставить "a","b"
arr.slice(1, 3);                          // копия части массива, исходный не меняется
arr.sort((a, b) => a - b);                // сортировка (без функции — как строки!)
arr.reverse();
arr.indexOf(x); arr.includes(x);
arr.join(", ");                            // массив → строка
"1,2,3".split(",");                        // строка → массив

arr.forEach((item, i) => console.log(i, item));
const doubled = arr.map(x => x * 2);
const evens = arr.filter(x => x % 2 === 0);
const sum = arr.reduce((acc, x) => acc + x, 0);
const hasNeg = arr.some(x => x < 0);
const allPos = arr.every(x => x > 0);
```
*Где пригодится: `map`/`filter`/`sort` — основной инструмент для сортировки/фильтрации/пагинации таблицы «Контакты» (п.3 ЛР3) и вывода каталога (п.5); в ЛР4 те же методы используются при рендере списков в React (`items.map(item => <Card .../>)`), поэтому отработать их в ЛР3 — прямая инвестиция в ЛР4.*

### Объекты, `this`, классы, прототипы

```js
const user = {
  name: "Вася",
  age: 25,
  sayHi() { alert(`Привет, я ${this.name}`); },   // метод
  get info() { return `${this.name}, ${this.age}`; },  // геттер
  set info(str) { [this.name, this.age] = str.split(","); } // сеттер
};
for (const key in user) console.log(key, user[key]);   // перебор свойств
"name" in user;              // проверка наличия свойства
delete user.age;             // удаление свойства
```
**Прототип** — объект связан со своим «резервным» объектом-прототипом через `__proto__` ([[Prototype]] по спецификации): если свойство не найдено в самом объекте, поиск продолжается в прототипе и далее по цепочке. `obj.hasOwnProperty(key)` отличает собственные свойства от унаследованных.

**Функциональный стиль + прототипное наследование** (вариант 1 из п.8 ЛР3):
```js
function Person(name) {
  this.name = name;
}
Person.prototype.greet = function () { return "Привет, я " + this.name; };

function Student(name, course) {
  Person.call(this, name);      // вызов конструктора родителя
  this.course = course;
}
Student.prototype = Object.create(Person.prototype);   // наследование прототипа
Student.prototype.constructor = Student;
Student.prototype.study = function () { return this.name + " учится на курсе " + this.course; };

const s = new Student("Аня", 3);
s.greet();  // унаследованный метод
```

**`class`/`extends`** (вариант 2 из п.8 ЛР3 — «синтаксический сахар» над прототипами):
```js
class Person {
  #email; // приватное поле (ES2022, поддерживается всеми актуальными браузерами)
  constructor(name, email) { this.name = name; this.#email = email; }
  get email() { return this.#email; }          // геттер
  set email(v) { this.#email = v; }             // сеттер
  addObject(obj) { this.items = [...(this.items || []), obj]; return this; } // метод добавления
  static fromForm(form) { return new Person(form.name.value, form.email.value); } // из формы
  printAll() { console.log(this.items); }        // вывод всех объектов
  toString() { return `${this.name} <${this.#email}>`; } // вывод результата
}

class Student extends Person {
  constructor(name, email, course) {
    super(name, email);           // обязателен до обращения к this
    this.course = course;
  }
  toString() { return super.toString() + `, курс ${this.course}`; }
}
```
*Где пригодится: ровно то, что требует п.8 ЛР3 — базовый класс + наследник, 5 методов (геттер, сеттер, добавление из формы, вывод всех, вывод результата), оба стиля.* `instanceof` проверяет принадлежность объекта классу (в т.ч. предку).

## 2. BOM и DOM

**BOM (Browser Object Model)** — объекты, которые браузер создаёт при загрузке страницы (`window`, `document`, `navigator`, `location`, `history`, `screen`). `window` — глобальный объект браузера. Основные методы `window`: `alert/confirm/prompt`, `open()/close()`, `setTimeout()/setInterval()` (+`clearTimeout`/`clearInterval`), `scrollTo()`.

```js
console.log(location.href, location.pathname, location.search, location.hash);
console.log(navigator.userAgent);
navigator.geolocation.getCurrentPosition(
  pos => console.log(pos.coords.latitude, pos.coords.longitude),
  err => console.log("Ошибка геолокации")
);
```
*Где пригодится: п.9 ЛР3 — «дополнительные API» — геолокация выше, синтез речи `speechSynthesis.speak(new SpeechSynthesisUtterance("Привет"))`, батарея `navigator.getBattery().then(b => console.log(b.level))`.*

**DOM (Document Object Model)** — дерево объектов, описывающее HTML-документ; часть BOM, доступна через `document`.

### Получение элементов

| Метод | Ищет по | Живая коллекция |

| `elem.getElementsByTagName(tag)` | тегу | да |

### Навигация

`parentNode/parentElement`, `childNodes` (включая текстовые узлы) / `children` (только элементы), `firstChild/lastChild` / `firstElementChild/lastElementChild`, `nextSibling/previousSibling` / `nextElementSibling/previousElementSibling`.

## 3. События

```js
btn.addEventListener("click", handler);      // можно навесить сколько угодно обработчиков
btn.removeEventListener("click", handler);   // требует ту же ссылку на функцию
```
Также возможны: атрибут `onclick="..."` в разметке и присваивание `elem.onclick = function(){}` (только один обработчик на событие).

**Объект события** (первый аргумент обработчика): `event.type`, `event.target` (где событие реально произошло), `event.currentTarget`/`this` (на каком элементе обрабатывается), `event.clientX/clientY`.

**Всплытие (bubbling)** — событие идёт от самого вложенного элемента вверх по дереву к родителям. `event.stopPropagation()` — остановить всплытие. Три фазы: **погружение (capturing)** → **цель (target)** → **всплытие (bubbling)** (третий аргумент `addEventListener(type, fn, true)` — слушать на фазе погружения).

**Делегирование событий** — один обработчик на общего предка вместо множества обработчиков на детях:
```js
table.addEventListener("click", e => {
  const row = e.target.closest("tr");
  if (!row) return;
  showDetails(row);
});
```
*Где пригодится: прямая рекомендация для таблицы «Контакты» ЛР3 (клик по строке, кнопка удаления в динамически генерируемых элементах п.4) — вешать один обработчик на `<table>`/контейнер, а не на каждую строку.*

**Отмена действия браузера по умолчанию**: `event.preventDefault()` (например, отменить переход по ссылке или отправку формы для собственной валидации).

**Формы**: доступ — `document.forms.myForm`, к полю — `form.elements.fieldName`; событие `submit` у формы; `form.submit()` — программная отправка **без** генерации события `submit` (не выполнит навешанную на него валидацию!).

**Генерация собственных событий**:
```js
const event = new CustomEvent("sliderChange", { detail: { index: 2 }, bubbles: true });
slider.dispatchEvent(event);
slider.addEventListener("sliderChange", e => console.log(e.detail.index));
```

**Валидация URL/телефона (п.3 ЛР3)** — регулярные выражения:
```js
function isValidUrl(url) {
  return /^https?:\/\/.+\.(php|html)$/i.test(url);

function isValidPhone(phone) {
```

```js
function httpGet(url) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open("GET", url);
    xhr.onload = () => xhr.status === 200 ? resolve(xhr.response) : reject(new Error(xhr.statusText));
    xhr.onerror = () => reject(new Error("Network error"));
    xhr.send();
  });
}
httpGet("/api/contacts")
```

## 1. Node.js и Express — сервер

**Node.js** — среда выполнения JavaScript вне браузера (движок V8), позволяет писать серверный код на JS. **Express** — минималистичный веб-фреймворк поверх Node.js для построения HTTP-серверов и REST API.

Библиотеки вроде `express`/`mongoose`/`cors`, которые ниже подключаются через `require(...)`, устанавливаются командой `npm install <имя>` — **npm** (Node Package Manager, менеджер пакетов) ставится вместе с Node.js; список зависимостей проекта фиксируется в файле `package.json`.

**Middleware** («промежуточный обработчик») — функция вида `(req, res, next) => {...}`, которая выполняется до того, как запрос дойдёт до обработчика маршрута: может изменить `req`/`res`, прервать запрос или пропустить его дальше вызовом `next()`. `app.use(...)` подключает middleware ко всем маршрутам приложения.

```js
// server.js
const express = require("express");
const mongoose = require("mongoose");
const cors = require("cors");
const app = express();

app.use(cors());              // middleware CORS (Cross-Origin Resource Sharing) — разрешает браузеру делать запросы на другой адрес/порт (без него запрос со страницы React к серверу Express на другом порту блокируется браузером)
app.use(express.json());      // встроенный middleware Express — разбор JSON в теле запроса

mongoose.connect("mongodb://localhost:27017/shopdb");

app.use("/api/products", require("./routes/products"));
app.use("/api/auth", require("./routes/auth"));

app.listen(5000, () => console.log("Server started on 5000"));
```
*Где пригодится: это стартовая точка сервера ЛР4 — весь REST API вешается через `app.use("/api/...", router)`.*

### Модели MongoDB через Mongoose (минимум 4 модели)

**Mongoose** — библиотека ODM (Object Data Modeling — «объектно-документное отображение») для Node.js: позволяет описывать структуру документов MongoDB через **схему** (`Schema` — объект, задающий, какие поля есть у документа, какого они типа и по каким правилам проверяются) и работать с документами базы как с обычными JS-объектами.

```js
// models/Product.js
const { Schema, model } = require("mongoose");

const productSchema = new Schema({
  name:  { type: String, required: true, minlength: 2, maxlength: 100 },
  price: { type: Number, required: true, min: 0 },
  description: { type: String, maxlength: 1000 },
  category: { type: Schema.Types.ObjectId, ref: "Category" },
  inStock: { type: Boolean, default: true },
  createdAt: { type: Date, default: Date.now },
  updatedAt: { type: Date, default: Date.now }
});

module.exports = model("Product", productSchema);
```
```js
// models/User.js
const bcrypt = require("bcryptjs");  // bcryptjs — библиотека для хэширования паролей (необратимого преобразования, чтобы пароль не хранился в открытом виде)
const userSchema = new Schema({
  email: { type: String, required: true, unique: true, match: /^\S+@\S+\.\S+$/ },
  passwordHash: { type: String, required: true },
  role: { type: String, enum: ["user", "admin"], default: "user" }
});
userSchema.methods.checkPassword = function (password) {
  return bcrypt.compareSync(password, this.passwordHash);
};
module.exports = model("User", userSchema);
```
Встроенные валидаторы Mongoose: `required`, `min`/`max` (числа), `minlength`/`maxlength` (строки), `enum`, `match` (regexp), `unique` (индекс). Кроме `Product`/`User` заведите ещё минимум 2 модели по своей предметной области (например, `Category`, `Order`/`Review`/`Booking` — в зависимости от варианта). *Где пригодится: прямое требование ЛР4 — «минимум четыре модели», «встроенные валидаторы», «подходящие типы данных» — шаблон выше и есть ответ.*

### REST-маршруты, CRUD, поиск, сортировка

CRUD как HTTP-методы: Create → `POST`, Read → `GET`, Update → `PUT`, Delete → `DELETE`.

```js
// routes/products.js
const router = require("express").Router();   // Router() — отдельная группа связанных маршрутов («мини-приложение»), которую потом подключают в основной app через app.use(...)
const Product = require("../models/Product");
const auth = require("../middleware/auth");   // проверка JWT (JSON Web Token — подписанный токен доступа, который сервер выдаёт после входа), см. ниже

// GET доступен всем (просмотр/поиск/сортировка — даже неавторизованным)
router.get("/", async (req, res) => {
  const { q, sort = "name", order = "asc", page = 1, limit = 10 } = req.query;
  const filter = q ? { name: new RegExp(q, "i") } : {};
  const products = await Product.find(filter)
    .sort({ [sort]: order === "asc" ? 1 : -1 })
    .skip((page - 1) * limit)
    .limit(Number(limit));
  res.json(products);
});

router.get("/:id", async (req, res) => res.json(await Product.findById(req.params.id)));

// CRUD — только для авторизованных (auth-middleware)
router.post("/", auth, async (req, res) => {
  const product = await Product.create({ ...req.body, updatedAt: new Date() });
  res.status(201).json(product);
});
router.put("/:id", auth, async (req, res) => {
  const product = await Product.findByIdAndUpdate(req.params.id, { ...req.body, updatedAt: new Date() }, { new: true, runValidators: true });
  res.json(product);
});
router.delete("/:id", auth, async (req, res) => {
  await Product.findByIdAndDelete(req.params.id);
  res.sendStatus(204);
});

module.exports = router;
```
*Где пригодится: прямые требования ЛР4 — «для авторизованного CRUD + поиск/сортировка», «для неавторизованного — только просмотр/поиск/сортировка/авторизация» — реализуется именно ограничением `auth`-мидлвара на изменяющих маршрутах при открытом `GET`.*

### Аутентификация по логину/паролю (JWT)

**JWT (JSON Web Token)** — компактный подписанный токен: сервер выдаёт его пользователю после успешного входа, а клиент затем прикладывает его к каждому запросу (в заголовке `Authorization: Bearer <token>`), чтобы сервер мог проверить подпись и узнать, кто делает запрос, не обращаясь к базе за сессией.

`process.env.JWT_SECRET` — секретный ключ, читаемый из **переменных окружения** (environment variables): значения, которые задаются не в коде, а в окружении процесса — обычно через файл `.env` (не попадает в git), чтобы пароли/ключи не хранились в открытом виде в репозитории.

```js
// routes/auth.js
const router = require("express").Router();
const bcrypt = require("bcryptjs");
const jwt = require("jsonwebtoken");
const User = require("../models/User");

router.post("/register", async (req, res) => {
  const passwordHash = bcrypt.hashSync(req.body.password, 10);
  const user = await User.create({ email: req.body.email, passwordHash });
  res.status(201).json({ id: user._id });
});

router.post("/login", async (req, res) => {
  const user = await User.findOne({ email: req.body.email });
  if (!user || !user.checkPassword(req.body.password))
    return res.status(401).json({ message: "Неверный логин или пароль" });
  const token = jwt.sign({ id: user._id, role: user.role }, process.env.JWT_SECRET, { expiresIn: "7d" });
  res.json({ token });
});

module.exports = router;
```
```js
// middleware/auth.js
module.exports = function (req, res, next) {
  const token = req.headers.authorization?.split(" ")[1];  // "Bearer <token>"
  if (!token) return res.status(401).json({ message: "Требуется авторизация" });
  try {
    req.user = require("jsonwebtoken").verify(token, process.env.JWT_SECRET);
    next();
  } catch { res.status(401).json({ message: "Неверный токен" }); }
```

## 2. React — клиент

**React** — библиотека для построения пользовательских интерфейсов из переиспользуемых компонентов; компонент — функция или класс, возвращающие описание разметки (JSX). **JSX (JavaScript XML)** — расширение синтаксиса JS, позволяющее писать HTML-подобную разметку прямо внутри JS-кода; браузер её не понимает — сборщик проекта (Vite/CRA/webpack) компилирует JSX в обычные вызовы функций JS (`React.createElement(...)`).

### Формы на React + клиентская и серверная валидация

```jsx
function ProductForm({ onCreated }) {
  const [form, setForm] = React.useState({ name: "", price: "" });
  const [errors, setErrors] = React.useState({});

  function validate() {
    const e = {};
    if (form.name.trim().length < 2) e.name = "Минимум 2 символа";
    if (Number(form.price) <= 0) e.price = "Цена должна быть больше 0";
    setErrors(e);
    return Object.keys(e).length === 0;
  }

  async function handleSubmit(ev) {
    ev.preventDefault();
    if (!validate()) return;
    const res = await fetch("/api/products", {
      method: "POST",
      headers: { "Content-Type": "application/json", Authorization: `Bearer ${localStorage.getItem("token")}` },
      body: JSON.stringify(form)
    });
    if (res.ok) onCreated(await res.json());
    else setErrors({ server: (await res.json()).message });   // ошибка сервера — тоже валидация
  }

  return (
    <form onSubmit={handleSubmit}>
      <input value={form.name} onChange={e => setForm({ ...form, name: e.target.value })} />
      {errors.name && <span className="error">{errors.name}</span>}
      <input value={form.price} onChange={e => setForm({ ...form, price: e.target.value })} />
      {errors.price && <span className="error">{errors.price}</span>}
      <button type="submit">Сохранить</button>
    </form>
  );
}
```
Серверная часть уже валидирует данные через Mongoose (`required`, `min`, `match` — см. модель `Product`) — при нарушении `save()`/`findByIdAndUpdate({runValidators:true})` вернёт `ValidationError`, которую сервер превращает в HTTP 400 с сообщением. *Где пригодится: прямое требование ЛР4 — «валидация форм и на сервере, и на клиенте» — комбинация формы выше + `runValidators: true` в маршруте `PUT`.*

```js
// XMLHttpRequest с прогрессом загрузки (например, загрузка фото товара)
function uploadWithProgress(file, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open("POST", "/api/upload");
    xhr.upload.onprogress = e => onProgress(Math.round((e.loaded / e.total) * 100));
    xhr.onload = () => xhr.status === 200 ? resolve(JSON.parse(xhr.response)) : reject(xhr.statusText);
    const fd = new FormData(); fd.append("file", file);
    xhr.send(fd);
  });
}

// setTimeout — автоскрытие уведомления + сохранение таймера в localStorage
function showToast(message) {
  const el = document.querySelector("#toast");
  el.textContent = message; el.hidden = false;
  localStorage.setItem("toastShownAt", Date.now());
  setTimeout(() => { el.hidden = true; }, 3000);
}

// Promise-цепочка с зависимыми шагами (пример для "Гостиницы": проверка -> бронь -> подтверждение)
function bookRoom(roomId, dates) {
  return checkAvailability(roomId, dates)
    .then(available => available ? createBooking(roomId, dates) : Promise.reject("Занято"))
    .then(booking => sendConfirmation(booking));
}
// тот же сценарий через async/await — более читаемый вариант
async function bookRoomAsync(roomId, dates) {
  const available = await checkAvailability(roomId, dates);
  if (!available) throw new Error("Занято");
  const booking = await createBooking(roomId, dates);
  return sendConfirmation(booking);
}
```

# Дополнительно

Материал ниже не требуется напрямую ни одной из 4 ЛР, но был на лекциях и полезен для общего кругозора/собеседований.

### Коллекции ES6: `Map`, `Set`, `WeakMap`, `WeakSet`

`Map` — пары ключ-значение с ключом **любого** типа (в отличие от объекта, где ключ всегда строка); `Set` — коллекция уникальных значений.
```js
const map = new Map([["a", 1]]);
map.set(2, "two").set(true, "bool");
for (const [k, v] of map) console.log(k, v);

const set = new Set([1, 2, 2, 3]);   // {1, 2, 3}
```
`WeakMap`/`WeakSet` — ключами/значениями могут быть только объекты; не мешают сборщику мусора удалять их, если объект больше нигде не используется (нет `size`, нельзя перебрать) — удобно для привязки «служебных» данных к DOM-элементам без утечек памяти.

### Модули ES6

```js
// utils.js
export const TAX = 0.2;

```
*Где пригодится: это тот самый `import`/`export`, которым написан любой React-проект в ЛР4 — сборщик (Vite/CRA/webpack) умеет собирать такие модули в один бандл.*

### Proxy

```js
const user = { name: "Alex" };
const logged = new Proxy(user, {
  get(target, prop) { console.log("чтение", prop); return target[prop]; },
  set(target, prop, value) { console.log("запись", prop, value); target[prop] = value; return true; }
});
```
`Proxy(target, handler)` — «ловушки» (`get, set, has, deleteProperty, apply, construct` и др.) для перехвата операций над объектом; основа многих современных реактивных библиотек (Vue 3 использует Proxy для реактивности стейта).

### Буферные и типизированные массивы

`ArrayBuffer` — «сырые» байты фиксированного размера; `DataView`/типизированные массивы (`Int32Array`, `Uint8Array` и т.д.) — читают/пишут его как массив чисел заданного типа. Используются там, где важна скорость и компактность (обработка бинарных данных, WebGL, работа с файлами).

### Emmet (ускорение вёрстки в редакторе)

`div>ul>li*5{Item $}` + `Tab/Ctrl+E` разворачивается в:
```html
<div><ul><li>Item 1</li><li>Item 2</li><li>Item 3</li><li>Item 4</li><li>Item 5</li></ul></div>
```
Основные операторы: `>` — вложенность, `+` — соседний элемент, `^` — подъём на уровень, `*` — умножение, `$` — автонумерация, `.`/`#` — класс/id, `{}` — текст внутри, `[]` — произвольные атрибуты. *Где пригодится: экономит время при вёрстке однотипных карточек/списков в ЛР1/ЛР2 (например, каталога партнёров).*
